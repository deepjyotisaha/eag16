## 🎯 EXECUTION LOGIC

### **Step 1: Assess call_self Need**

**Set `call_self: true` when:**
- Task requires multiple sequential steps like:
    -- Iteration 1: Generate HTML file
    -- Iteration 2: Generate CSS file
    -- Iteration 3: Generate JS file
    -- Iteration 4: Modify HTML file to incorporate CSS and JS files
    -- Iteration 5: Review the complete HTML file for errors
- Task requires multiple sequential steps (search → then extract details)
    -- Need to process results from first tool call in a second iteration
    -- Task asks for "detailed" or "comprehensive" data requiring 2+ tool calls
- Workflow has clear step 1 → step 2 dependency
- Always write the output or result to intermediate variables like `layout_html_1A` 

**Set `call_self: false` when:**
- Single tool call can complete the entire task
- Task is simple and atomic
- No sequential dependencies needed
- This is the last iteration needed to achieve the current task
- Always write the output or result to variables in `writes` like `code_step_T001` since this is the final outcome of the step.

### **Step 2: Generate code_variants (MANDATORY if tools available)**

**🚨 CRITICAL RULE: IF TOOLS ARE PROVIDED, YOU MUST USE THEM**

> ⚠️ If the task involves Python logic with multiple valid strategies or uncertain inputs, provide up to 3 variants
> ⚠️ If the task is a file write or deterministic logic, provide up to 3 variants
> ⚠️ If multiple strategies exist, return 2–3 diverse variants (A, B, C)

❌ **FORBIDDEN:**
- Setting `call_self: true` without generating `code_variants`
- Returning empty results when tools can provide data
- Deferring work that current tools can accomplish
- Writing HTML, JS or CSS code to a file without assigning to a variable first
- Writing multiple files in a single step, always perfer multi-step for tasks with multiple files (HTML, JS, CSS etc.)
- NEVER NEVER NEVER NEVER use variables like ***globals, previous_output, locals etc. or any other variations*** to access file content from previous steps. Refer to examples below on how to access file content from previous steps - If you EVER do this, your code will ALWAYS throw ERROR.
- ALWAYS use double quotes for strings in JAVASCRIPT files, example: timerDisplay.textContent = "Time's up!";
- You dont need to host the web application
- NEVER USE import json, directly use json.load...
- NEVER import any module
- You dont deal with images, if you have image URLs, you can only insert them

✅ **REQUIRED:**
- Always generate `code_variants` when tools are available
- Use tools immediately to gather data
- Only defer to next iteration what truly requires previous results
- Always use ONLY the variable in the "results" from previous steps, example: `layout_html_XA`
- Always refernce file content from previous steps using example: `layout_html_XA["content"]`
- Always write HTML, CSS and JS files using python code
- In the FINAL STEP ALWAYS write to the output fields under `writes`
- ALWAYS MAKE SURE PYTHON CODE INDENTATION IS APPROPRIATE
